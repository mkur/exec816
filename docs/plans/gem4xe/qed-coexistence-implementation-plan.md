## Rules for every slice

Use optimized emitted code and the pinned compiler/ROM/emulator. Hash current
source, APP/provider, observer and media inputs. Preserve prior reports and the
user's writable disk. Use fresh output directories and disposable WORK images.
Report development scope and actual case counts; run no full qualification
matrix unless a demonstrated change requires its targeted deeper cases.

Keep one current ABI and implementation. Donor changes use ordered patches.
No production instrumentation, new private service or larger Task pool is
planned. If measurements require a fix, implement it in its owner, run focused
regressions and repeat only affected cohorts with matching inputs. Record any
design amendment before depending on a changed budget.

Report reservation deltas **0 fixed / 0 per-public-Task / 0 private idle
bank-zero bytes**, including guards, alignment and unused reserved capacity,
unless an explicitly measured fit decision changes that target. Keep upper
heap, aligned image backing and per-application costs separate.

## QC1 Production baseline

The initial baseline's insertion limit failed because every character marked
the whole viewport dirty. Implement and commit QC1a's focused row-damage fix
before completing this baseline; retain the original failure and unchanged
acceptance limits. The [history](../../history/qed-coexistence.md) records this
additional executable slice.

Add a host observer for the normal loaded production APP, reusing existing
physical input, document and pixel oracles. Resolve its relocated symbols and
matching target-emitted C offsets. Reject stale source/layout/provider inputs.
Read the native heap's published free lists at paused checkpoints, checking
extent bounds, alignment and totals; add focused host tests for this parser.

Create a separate development copy of the verified native preview with its
exact OF816 ZIP. Add stress documents only to the disposable writable test disk.
Run one baseline Open/Edit/Undo/Navigate/Find/Save/reopen/Quit session. Record
key-to-scanout samples, form/completion timings, heap/private snapshots, live
Tasks, normal ownership return and independent persisted-byte/allocation audit.
Keep this runnable before adding load. Apply the design's response limits now.

## QC2 Admitted concurrent workloads

Before its warmed idle baseline, launch and collect Counter twice. Identify
the desktop-owned path/timer allocations, record their 368-byte first-use upper
backing, and require identical repeated warm heap extents. Then extend the same
scenario to an ordinary loaded Counter APP. Check its timer
progress during QED input and a held form, cover/expose QED, and validate the
restored pixels. At eight live Tasks, one extra command must fail normally and
restore its temporary ownership. Close and collect Counter before the next
cohort.

While Counter is live, also use the owning shell's ordinary BREAK command to
request QED Stop, hold and Cancel its modified decision, and verify peer
progress and resumed editing. Run BREAK through ordinary EXECUTE with a
temporary alias and a comment-reading delay, returning input to QED before
the decision opens; remove the alias afterward. This uses no additional Task.
This supplies the Stop-with-peer part of the
lifetime gate through the production launch path.

Run QED with foreground shell CKSUM reading an unrelated large WORK file. QED
already occupies that shell's single background job; do not attempt a second RUN.
Verify the command is still live during measured input, its read/computation
progress advances, and it eventually reports the independently computed
checksum and length. Both cohorts use the same production APP and workflow as
QC1, with independent disposable media. Record all latency samples, Task peaks,
heap checkpoints and closed-image bytes. Diagnose and fix a measured failure
in a separate executable slice if necessary; do not add speculative VDI work.

The integration follow-up corrects the native desktop's shown-window selector
without using input-wait interest as window visibility. Rebuild the native demo,
provider and production APP before its final Counter/CRC cohorts, and compare
complete bank-zero reservations with the earlier preview. Existing focused C
fixtures remain identified separately for their unchanged QED source/ABI paths.
Observe long checksum completion in bounded progress intervals, rather than
applying the one-operation wait to the whole 512 KiB command.
Complete content painting before caption publication, including clamp and
scroll-owner exits; verify caption ordering in the actual-source damage probe.
Repeat the normal cohorts and affected rendering/lifetime fixtures with this
final patch set before reconciling the gate.

## QC3 Repeated lifetime and failures

Add a targeted four-lifetime emitted fixture derived from the current saving
and cursor observers. Keep an ordinary peer alive during the first editing
session. Exercise a larger document, clipboard/Undo retention, line-allocation
refusal and form-allocation refusal; successful calls still use the production
implementations. Verify unchanged bytes after refusal, then successful editing,
Cancel, Quit and cooperative Stop Cancel/Discard. Check peer progress through
the relevant waits and exact warm heap restoration after collection.

Capture private backing and native heap fragmentation at comparable points,
plus selected source/native/IRQ stack headroom and guards. Bind the same ordered
production patches as QC1/QC2. This is targeted failure/reuse coverage; retain
the original QW operational fault records without rerunning their full matrix.

## QC4 Gate and handoff

Reconcile all three cohorts and lifetime checks with current production
APP/resource, C ABI/provider, source-frame ledger, compiler, ROM/emulator and
normal demo ZIP. Verify retained package checksums, OF816 five-second startup,
license notices and source inputs. Reuse byte-identical verified production
artifacts; a production change requires a matching demo refresh and affected
workflow rerun. Keep local launch settings and user WORK storage untouched.

Run affected host tests, content/local-link checks and `git diff --check`.
Record actual execution scope, measured response maxima, memory/fragmentation,
Task admission, stack headroom and full bank-zero accounting. Update the
strategy and relevant indexes only after every selected gate passes. Step 7
then covers supported launch/delivery, final scope reconciliation and any
requested release qualification/publication, including required CAR/BIN files.

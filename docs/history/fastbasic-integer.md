qualification remain separate.

The integer runtime and command-line compiler are ported from FastBasic 4.7
sources. EDX edits a WORK: source, FBCI compiles it on the Atari, and the ordinary
shell loads the fresh `.COM` output after the compiler retires. Text and 80×30
bitmap demos use the same guest/native backend. Floating point and the donor
integrated editor remain FB6/FB7 follow-ons, as agreed for this delivery.

## Source and execution choices

Pins and full source hashes live in [ports/fastbasic](../../ports/fastbasic/README.md).
The build verifies both archives, original cached sources and patched input
sources; a clean build without reused host binaries reproduces the FBCI hash.
Five original integer compiler/runtime controls pass in the pinned mini65
Atari OS simulator. This is not an original SDX/Altirra or physical Atari control.

The port moves mutable dispatch and MOVE code out of zero page, retains only
D-relative data there, and uses private-bank absolute JMP operands for computed
dispatch and the compiler's internal callbacks. Ordinary indirect JMP would
read a pointer in bank zero. PEEK/POKE and their word forms explicitly handle
the virtual low-page alias, including the `$FF` word boundary. Parser ROM
helpers, integer STR, timer/random access and direct OS console vectors are
replaced with source helpers or native services. Startup no longer closes
borrowed CIO channels or initializes sound.

The on-machine frontend normalizes ATASCII, LF, CRLF and CR, adds a missing final
EOL, reads Process arguments, reports parser locations, and checks every save
and final Close. It captures ERR() before printing a diagnostic. Fatal cleanup
belongs to the native adapter, so a later Close failure cannot replace a write
failure. Runtime allocation errors explicitly report 103 even after an earlier
CIO error that BASIC handled through ERR().

The executable profile was simplified from the plan's general segment proposal
to one bounded initialized segment plus implicit zeroed workspace. It covers the
selected source target with fewer loader records and overlap cases. The
versioned header and exact extent checks remain; no old profile or arbitrary
Atari XEX compatibility path is added.

`tools/audit_fastbasic.py` traverses 1,347 instructions from the linked handlers,
parser entry and callbacks. It records 16 service transfers and two reviewed
mutable jumps. It finds no unreviewed external code transfers in those paths.
Thirteen absolute data operands need source interpretation: private variable
page operands based at `$FF00`, plus private RAM aliases in the linked but
grammar-excluded PMGRAPHICS body. Parser action-table RTS transfers, dynamic
pointer aliasing and stack bounds are not proven by this static traversal.
The donor IDE's `compile.asm`/BRKKY implementation is not linked; FBCI uses
`cmdmenu.asm`.

## Memory and scheduling

Fixed, root, kernel, per-Task and idle bank-zero reservation deltas are **zero**
relative to the SDX-enabled build, including alignment, guards and unused space.
The existing two guest D pages and outer guards occupy 544 fixed bytes. SDX and
FastBasic share that pool and the existing 64-KiB resident bridge reservation.
No extra Task, bank-zero trampoline or private kernel operation is introduced.
The final optimized text demo contains 14,882 bytes of FastBasic module code
in upper RAM, excluding reused native routines and shared loader/Process edits.
Its existing SDX image-data arena remains 12 KiB; the build map records occupancy
and unused capacity rather than charging that reservation to bank zero.

Each retained FastBasic Image owns 131,072 reserved upper bytes for its aligned
64-KiB bank, a 2,304-byte native session, the existing 72-byte Image record, and
its complete file snapshot rounded to eight bytes. The session adds 14 bytes
over the unchanged SDX session layout. Current FBCI is 5,970 bytes, so its
retained Image allocations total 139,424 bytes before ordinary Process/DOS and
on-demand timer resources. Loading temporarily holds the input file as well.
The bank backing total includes its unused alignment capacity.

FBCI's linker gives it D offsets `$80–B8` (57 used, 112 linker-reserved), with
the full guarded 256-byte guest D page charged to the shared pool. Its heap
starts at `$4800`; source, generated bytecode, variables and strings compete for
space below `$E000`. This is not a larger-document claim based on 4 MiB RAM.

Dispatch checkpoints occur every 64 bytecodes from the first dispatch onward;
copy/fill checkpoints occur every 256 bytes, with a parser checkpoint per line.
The ordinary dispatch path has a calculated 65-cycle 6502 instruction cost,
plus page-boundary adjustments and native checkpoint service time. This is an
instruction estimate, not a measured end-to-end speed comparison with Atari
FastBasic. The coexistence checks measure actual peer progress and no-I/O BREAK
completion within two PAL ticks, including the selected forced native NMI return
boundary. Selected native stack observations preserve interrupt headroom and
guards; the JSON retains their exact values.

## Validation scope and remaining gates

The evidence records original controls, raw/optimized focused ABI behavior,
optimized language/compiler/file tests, two guests and a native peer, BASIC
beside SDX MD5, retained-image relaunch, two-slot exhaustion/recovery, malformed
profiles, native/guest guards, heap recovery and OS restoration. Fault builds
inject short writes, write failures and late Close failures at the DOS boundary
while keeping real file ownership. These are explicit test-only overrides;
production modules contain no injection seam.

The packaged walkthrough uses physical keys to edit and save in EDX, compiles
and runs that saved file, checks bare FBCI prompts, INPUT/GET/KEY, redirection,
empty sources, parse errors, read-only output, allocation failure, BREAK and
subsequent native/MD5/ARC commands. It reads the writable ATR back and checks
both source bytes and fresh executable headers. OF816's five-second autoboot,
the extracted ZIP's ROM/disks, display pixels, guards and orderly EXIT use the
existing demo harness. Both Atarimax CAR variants and raw BIN wrap the matching
boot XEX; packaging checks their contents and checksums.

FB0–FB5's functional integer delivery is implemented. This development evidence
does not close every deeper acceptance case in the original plan: exhaustive
IRQ/NMI transition matrices, physical hardware, maximum source/string/array
capacity qualification, parser/save-phase BREAK timing, and pointer-IRQ/focus
stress during compilation remain open. The first useful workflow is available;
those additional gates must be run before broader compatibility or qualification
claims. Floating point and the integrated editor are not part of this delivery.

The boot ZIPs contain boot files, user guides, notices and checksums. The
separate `exec816-fastbasic-source.zip` supplies the modified donor and current
Exec sources with build instructions and notices. Build manifests, intermediates
and test output stay outside the boot ZIPs. No implementation commit is implied
by these artifacts.

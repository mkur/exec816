# FastBasic source interpreter delivery

[Historical records](README.md) · [Language contract](../reference/fastbasic.md) ·
[Workbench contract](../reference/fastbasic-workbench.md) ·
[Implementation plan](../plans/fastbasic-interpreter-implementation-plan.md)

FB and FBI run BASIC source in one ordinary Exec Process. FB includes integer
and floating point; FBI is integer-only. BASIC.APP Run attaches an immutable
unsaved source buffer to the same engine. Parsing produces bytecode inside its
private bank, then enters the existing runtime without clearing that code.
Run creates no source, COM or diagnostic scratch files. FBC/FBCI and workbench
Check/Build retain their existing standalone compilation behavior.

The graphical walkthrough also exposed an existing console redraw defect:
the ATASCII mode bit was passed as a palette index when the scene painter
re-exposed a console window. The presenter now receives its own encoding flag;
clipped drawing uses the caller's explicit encoding so another console's mode
cannot affect editor or menu text.

## Implementation

FI0–FI7 add the maintained assembly source wrapper, complete linked user
runtimes, native bounded source admission, structured completion, public
attachment, editor integration and matching packages. The source/result records
come from `abi/fastbasic-interpreter.json`; the engine capability is identified
inside the admitted FB65 image. The common target advances to `$4704`, native
provider ABI to 20 and C import ABI to 25. Rebuild consumers together.

Source admission counts up to 32,768 original bytes and 255 bytes per line.
Both file and buffer modes normalize LF/CRLF/CR/ATASCII in at most 1 KiB units.
A file needs explicit EOF and successful Close before parsing. Errors never
execute partial source. Completion preserves the first fatal cause and is
copied to the caller before ordinary Process completion; the editor reads it
after collection. No new kernel operation or private controller Task is added.

Each Run has fresh runtime state. The parent can release its Image after Start;
execution retains it. A refused Start preserves the attachment for retry, an
invalid replacement preserves the admitted descriptor, and a retained Image
needs explicit reattachment for another buffer run. END and Stop fully retire
that invocation. Direct mode, Pause/Continue, variable inspection, native
graphics and enlarged/banked BASIC storage remain separate work.

## Memory

All FI slices add **0 reserved bank-zero bytes**: fixed/root/kernel, every
public Task and private idle, including guards, padding and unused capacity.
The twelve-Task profile still reserves 55,008 bytes and leaves 10,528 free.
The shared two-guest DP reservation remains 544 bytes; one source engine uses
one slot and one existing native Process stack.

The provider table needs 1,881 serialized bytes in 1,888 bytes of capacity.
Its capacity grows by 32 upper bytes, moving the existing 160-byte pointer
state from Task-bank offset `$4740` to `$4760`. It now reaches `$4800`, where
the unchanged capture reservation begins. The full reserved upper Task bank
does not grow.

| Upper allocation | Bytes |
| --- | ---: |
| Aligned guest-bank backing reservation | 131,072 |
| Integer engine snapshot, file / rounded allocation | 5,601 / 5,608 |
| FP engine snapshot, file / rounded allocation | 9,046 / 9,048 |
| Native session, requested / rounded | 2,314 / 2,320 |
| Source extension, requested / rounded | 1,564 / 1,568 |
| Image, requested / rounded | 74 / 80 |
| Editor immutable snapshot capacity | 32,768 |
| Editor job static storage | 2,543, including a new 128-byte result |

The session grows by four requested/eight rounded bytes for every FastBasic
Image; only source engines allocate the extension. Ordinary Process/DOS/console
and timer records are shared services. The cooperative loader also retains its
43-byte request (48 rounded), 1 KiB read buffer and staging allocation up to
262,144 bytes while loading. Staging and the retained engine snapshot coexist
during admission. Editor document allocation remains 65,544 rounded bytes.

FBI source starts at `$4600`, FB at `$5400`, with guest MEMTOP `$E000`.
Source, generated bytecode, variables, parser tables and array/string storage
compete for that range. In the small-source boundary fixture, byte arrays of
39,165 bytes in FBI and 35,581 in FB succeed; the next byte fails with 103.
These are measured cases, not a general heap guarantee for 32 KiB documents.
Code-expanding source can exhaust parser space. Large numbers of source lines
also incur a parser checkpoint per line.

## Development evidence

The [frozen record](../development/fastbasic-interpreter.json) contains engine
maps/audits, actual source/compiler/ROM/emulator identities, local test overrides,
native stack observations and the exact package hashes. The test tier is
development; selected asynchronous-entry checks do not qualify the entire
hosted system or physical hardware.

- The integer/FP corpus executes strings, arrays, procedures, native files,
  arithmetic and clocks. Admission adds 271 checks; injected Read/Close/output
  failures and parser/runtime OOM add 189. Another 131 checks cancel during
  acquisition, Close, parser work and the parse-to-execute transition, then
  rerun successfully. The array boundary fixture passes 71 checks.
  A focused native text-console fixture passes 54 checks for integer/FP output,
  inherited streams, exact redirected bytes, guards and resource return.
- Attachment runs 164 checks in each raw/optimized build, including upper
  pointers, empty source, full-width overflow, wrong engine, atomic replacement,
  all-Task refusal/retry, early release and reattachment. Injected DOS setup
  failure verifies that collection ends a returned child's borrow, while a
  configured Start returning zero preserves it for retry. Small C record/context
  probes pass 15 checks in each mode. The complete host suite passes 554 tests.
- Integer and FP lifetime fixtures pass 143/145 checks with two source guests,
  native-peer progress, guest overflow, retained-image relaunch, MD5/ARC,
  Task exhaustion and execution in high Task slot 8. The FP fixture forces
  actual VBI during decimal execution and selected NMI at the native return
  gate. Guards, heap/ownership return and normal OS restoration pass.
- BREAK observation takes zero to one tick across these busy-loop runs;
  full retirement takes three. In the lifetime fixture, the source Process
  touches 403 bytes of its 1,312-byte native stack, leaving 653 above the 256-byte interrupt
  floor. The final coexisting case reaches 475 bytes, leaving 581.
- The extracted OF816 demo exercises shell FB/FBI and unsaved integer/FP Run,
  error/fix, physical INPUT/GET/KEY, busy Stop/repeat, output close, Check/Build,
  output re-exposure, Quit during engine loading and orderly Quit with two
  shells. Run reserves no scratch names. The second
  shell plus BASIC and a pipeline reaches ten Tasks; BASIC execution reaches
  nine. The published standalone control runs after the IDE exits.

Focused phase timing uses coherent PAL tick samples and RAM source/output,
with test-only instrumentation. First/repeated FBI runs reach execution at
16/15 ticks and collection at 19/19; FB reaches execution at 17/17 and
collection at 21/21. One tick is 20 ms on this pinned PAL configuration.
Engine load takes 6–9 ticks, source acquisition/normalization 2–3 and parsing
one for these tiny programs. First native output and final cleanup are recorded
separately. These measurements exclude physical disk cold-start and GUI
repaint/input latency. Prior WB9 records and maps were retained, but no matching
fresh WB9 phase baseline exists; no numerical speedup factor is claimed.

## Packages

The development directory contains `demo-final/exec816-demo.zip` and
`demo-final/launch-altirra.command`. The ZIP includes OF816, its five-second standard
startup, matching SYS/WORK disks, pinned ROM, short guide, notices and complete
checksums. It contains no cartridge artifacts or build/test intermediates.

`exec816-fastbasic-source.zip` is separate. It contains the complete modified
FastBasic/cc65/mini65 tree and this Exec source snapshot. The clean rebuild uses
those sources without downloads, plus installed Calypsi 5.18 for BASIC.APP,
and compares both source engines, both compilers, BASIC.APP and a generated
standalone control byte for byte. The source archive's companion checksum and
rebuild report stay outside its embedded record to avoid a self-hash cycle.

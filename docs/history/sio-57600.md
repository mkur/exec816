# Nominal 57.6 kbaud SIO

> Historical record: applies to the revisions and profiles described below.
> See the [current documentation](../reference/device-io.md) and [history index](README.md).

The resident shell's [mount configuration](../../config/shell-sdfs.json) selects
`SIO_PROFILE_GENERIC57600` (4). In AltirraSDL choose **Generic + 57600 baud**
for D1; the bridge setting is `diskemu=generic56k`. Rebuild programs when changing
their mount profile. Changing only the emulator's drive mode does not change
the baud rate used by an existing XEX.

This remains an explicitly selected high-speed profile. Stock 810/1050 drives
normally use nominal 19.2 kbaud; 57.6 kbaud requires a compatible peripheral.
There is no speed negotiation, automatic retry or baud fallback. The earlier
125 kbaud profile remains available for compatible drives and timing tests.

## Clock and transaction contract

The [public ABI](../../abi/sio.json) adds one profile constant without changing the
52-byte IOSIOReq, gateway, descriptor, IRQ engine or scheduling protocol.
The worker uses POKEY divisor 8 for both command and data phases. Altirra's
`diskprofile.cpp` advertises high-speed index 8 for Generic57600 and admits
that command rate.

With the pinned PAL base clock of 1,773,447.5 Hz, observed host TX is 30 base
cycles per bit (**59,114.917 baud**); the emulated peripheral sends at 31
cycles per bit (**57,207.984 baud**). “57600” is the peripheral profile's
nominal name. It is not an exact fractional POKEY clock setting.

The profile accepts nonzero payloads up to 128 bytes and exactly 256 bytes for
READ (`$52`). NONE requires zero payload. Intermediate sizes, 256-byte writes,
unmapped/bank-zero buffers and invalid directions remain rejected. A block
volume may have 128- or 256-byte data sectors, with the first three sectors
always 128 bytes. Mount geometry remains explicit.

Default/maximum active timeout is 1,000,000 microseconds; an explicit timeout
must be at least 4,041 microseconds. Recovery rules are unchanged. In particular,
an uncertain timeout leaves SIO offline until a platform reset; correcting a
drive-mode mismatch requires a fresh cold launch.

## Validation

The [qualification record](../qualification/sio-57600.json) records the pinned
compiler, ROM, emulator, actual clock observations and raw/optimized execution.
It covers queued reads, 128-byte write/read-back, two units and a running
background Task; 128/256-byte sector boundaries with buffers crossing a bank;
rejected lengths, deadlines and unknown profiles; the real resident shell with
physical keyboard input; and a complete 70,003-byte DOS.Read with byte-wise
verification. The original 125 kbaud sector profile is checked as a regression.

Stack/domain guards, heap/ownership cleanup and OS restoration are checked by
the native harnesses. This is emulator evidence, not a physical-drive stability
measurement or a new eight-busy-Task latency qualification.

Reserved bank-zero change: **0 fixed bytes and 0 bytes per Task**, including
guards, alignment and spare capacity. The profile adds no buffer or descriptor
reservation. Exact file sizing still walks every sector in a file, so root DIR
on the large qualification fixture takes minutes. The default
[shell playground disk](../guides/shell.md) now contains only small text files.

Reproduce with `CARGO_INCREMENTAL=0 CARGO_PROFILE_DEV_DEBUG=0
CARGO_PROFILE_TEST_DEBUG=0` in the environment and the compiler from
[the pin](../../toolchain/actionc.json), at `build/actionc`:

```sh
python3 tools/test_sio_sectors.py --case opt --profile 4 --output build/sio-57600/sectors-opt
python3 tools/test_sio_device.py --case opt --speed 3 --trace --output build/sio-57600/queued-opt
python3 tools/test_shell_entry.py --case opt --paced --output build/sio-57600/shell-opt
python3 tools/probe_dos_large_read.py --case opt --profile 4 --paced --output build/sio-57600/read-opt
```

Repeat each with `--case raw` and a separate output directory. The queued
raw run needs no `--trace`. For the retained 125 kbaud sector regression, use
`--case opt --profile 1`.

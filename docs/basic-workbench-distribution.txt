
FastBasic workbench
-------------------

From Shell, type RUN C:BASIC.APP. The twelve-Task layout allows a second shell
beside the workbench and its interpreter Task. Output windows and AES
clients have separate limits; close extra applications when those are full.

Type PRINT 1.25*2.0 and press Control+Return: output should contain 2.5.
Run interprets the unsaved buffer without source, COM or diagnostic scratch files.
Program > Integer mode selects FBI for Run; floating point (FB) is the default.
Control+Shift+Return checks with FBC/FBCI without running. Parse errors select the source
byte and reveal folded lines. Successful Run returns to the editor position.

Select FastBasic output to enter INPUT/GET/KEY; select FastBasic for shortcuts.
Control+K, Program > Stop or closing output cancels the current run. Program > Output
reopens completed output. Quit waits for the run before Save/Discard/Cancel.
Run keeps the interpreter Process and BASIC state between runs. Try
A=A+1:PRINT A twice: it prints 1, then 2. Program > Restart interpreter clears
BASIC state while keeping the source. Changing Integer mode also resets it.
Repeated DIM keeps arrays of the same type and size; Restart before changing
those declarations. An idle interpreter continues to occupy a Task/guest slot.
Source edits are frozen during a job; Save and Save As remain available.

From Shell, FB WORK:CALC.BAS and FBI WORK:HELLO.BAS run source directly.
FB WORK:DECIMAL.BAS demonstrates decimal INPUT; BREAK stops FB WORK:BUSY.BAS.
FB/FBI require one source path. Source input is limited to 32 KiB, and its
parser, bytecode and variables still share one 64 KiB guest bank.

Control+B builds a standalone release COM. Choose WORK: as its destination.
Build does not save the source. Close the editor, then run the COM from Shell.
If publication or cleanup reports recovery paths, keep those copies; File >
Recovery paths displays build paths in output. RAM: contents vanish on reboot.

This first workbench delivery includes editing, Check, Run, Stop and Build.
Source debugging and native graphics are pending. FBC/FBCI remain available
from the shell, including the EDX edit/compile/run workflow.
Resident SDX and BASIC execution
-------------------------------

MD5, ARC and EDX are installed on SYS:C/. Their names work without .COM.
One SDX or BASIC guest can execute at a time. EDX keeps that ownership while
waiting for a key. A second guest reports error 202 (object in use).

An idle FastBasic interpreter releases execution ownership while keeping its
Process, variables, arrays, strings and open channels. MD5, ARC, EDX and
Check/Build can run between BASIC runs. A busy Run preserves BASIC state.
Restart interpreter explicitly clears that state. INPUT, PAUSE and a running
loop retain execution ownership until completion or Stop.

Very deeply nested BASIC syntax reports "too long". ARC compression reports
resource error 158 if its recursive tree walk reaches the stack limit; owned
archive cleanup then preserves the original archive.
